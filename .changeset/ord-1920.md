Lighter, Ondo, and Hyperliquid data reads now throw a typed `PerpsError` for the account's access state, instead of returning an empty result. Each code names one fact: `SetupRequired` (no credential is stored, and the SDK sends no venue request), `Unauthorized` (the venue rejected the credential the SDK sent), and `AccountNotFound` (the wallet has no account at the venue). An account with no rows still returns an empty list. Status reads keep returning the state as a value.

- Lighter `getOrders`, `getOrder`, `getFills`, `getActivity` and `getPortfolioHistory`: `SetupRequired` when no auth token resolves, `Unauthorized` when Lighter rejects the token, `AccountNotFound` when the wallet has no Lighter account. These reads previously returned an empty result, and `getOrder` threw `SDKError`, when no token resolved.
- Lighter `getPositions` and `getWithdrawableBalances`: `AccountNotFound` when the wallet has no Lighter account. They previously returned `[]`. They need no auth token.
- Lighter `getAvailableToTrade`: needs no auth token, and throws `AccountNotFound` when the wallet has no Lighter account (unchanged). It reads the fee tier through `getAccount`, so when the wallet's locally stored API key matches the registered key and Lighter rejects the resolved token, it throws `Unauthorized` (unchanged). Lighter `getMarketSettings` returns the venue default for a wallet with no account (unchanged).
- Lighter WebSocket account channels: `SetupRequired` at subscribe time when no auth token resolves, before the account lookup, so a wallet with no token and no account gets `SetupRequired` from `subscribe()` as from `getOrders`. They previously threw `Unauthorized`.
- Lighter WebSocket account channels with no auth-token resolver wired (no `lighterProvider()` on the client and no `resolveAuthToken` option): `SDKError`, because no account setup can satisfy an integrator wiring fault. They previously threw `Unauthorized`.
- Ondo `getWithdrawableBalances`, `getAvailableToTrade`, `getMarketSettings`, `getPositions`, `getOrders`, `getOrder`, `getFills`, `getActivity` and `getPortfolioHistory`: `SetupRequired` when no session token is stored, `Unauthorized` when Ondo rejects the stored session token. The provider removes a rejected token, so the next read throws `SetupRequired`. These reads previously returned an empty result, `getOrder` threw `SDKError`, and `getMarketSettings` threw `OndoSessionExpiredError` (`Unauthorized`) when no session was stored.
- Ondo WebSocket account channels: `SetupRequired` at subscribe time when no session is stored. They previously threw `OndoSessionExpiredError` (`Unauthorized`).
- Hyperliquid `getAccount`, `getWithdrawableBalances`, `getAvailableToTrade`, `getMarketSettings`, `getPositions`, `getOrders`, `getOrder`, `getFills`, `getActivity` and `getPortfolioHistory`: `AccountNotFound` when `preTransferCheck` reports that the wallet has no Hyperliquid account. Hyperliquid requires no read credential.
- Hyperliquid `orderUpdates`, `fills`, `positions`, `spotBalances`, `accountSummary` and `availableToTrade` WebSocket subscriptions: `AccountNotFound` at subscribe time when the wallet has no Hyperliquid account, before opening a venue channel.
- Unchanged status reads: Lighter `getAccount` (`apiKeyRegistered: false` and a zero fee tier when the wallet has no locally stored API key matching the registered key; otherwise it reads limits with the resolved token and throws `Unauthorized` if Lighter rejects it), `accountExists` and `getDepositFlow`; Ondo `getAccount`, `accountExists`, `getDepositFlow` and `getWithdrawFlow`; Hyperliquid `accountExists` and `getDepositFlow`.
- `@lifi/perps-sdk`: `PerpsClient.getAvailableToTrade` falls back to the account summary only when the provider has no per-market figure for the market. A provider read that throws propagates. TSDoc on the affected `PerpsClient` reads and services lists `SetupRequired`, `Unauthorized` and `AccountNotFound`.
