Surface `referralApplied` on `LighterAccountConfig`: `getAccount` reads (SDK-direct, per-user) whether any referral is already applied to the account, and `SET_REFERRAL` now projects `satisfied` from it. A referral is immutable once set, so an account carrying another integrator's code is treated as satisfied rather than being gated on a write Lighter would reject.
