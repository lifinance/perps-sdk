Lighter `TRANSFER` now collects the user's L1 wallet signature and embeds it as `txInfo.L1Sig`, so the stored API key alone cannot move USDC to an L1 address the account owner never approved. **Breaking:** a `TRANSFER` step now requires `userWallet`, and `LighterSigner.sign()` throws for `TRANSFER` — callers must use the new `LighterSigner.signTransfer()`. `SEND_ASSET` is unchanged: the same-account route move stays on the bare signer call, prompts no wallet, and keeps `L1Sig` empty.
