Add a Hyperliquid explorer client and set `explorerLink` on order rows that have no fill yet. `fetchUserTransactions` reads the address's recent HyperCore transactions from the explorer RPC, `getClientOrderIds` returns every client order id an action names, and `matchOrderActionHash` returns the hash of the transaction that names a given client order id. `getOrders` makes one explorer read per call and links each row whose `clientOrderId` a transaction in that window names, so an open, pending, triggered, cancelled, or rejected order now carries an explorer URL. The read is skipped when no row carries a `clientOrderId`, and an explorer failure leaves the rows unlinked instead of failing the order read. Every Hyperliquid REST failure but a caller abort now reaches the caller as a `PerpsError`: a 2xx body that is not JSON raises `ServerError` instead of a `SyntaxError`, and an abort rejects with the abort reason untouched instead of a `ServerError`.
