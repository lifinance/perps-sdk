If a caller aborts a request with a custom reason or with `AbortSignal.timeout()`, the request rejects with `signal.reason`, not with `PerpsError(ServerError)`. For this cancel, `fetchWithRetry` does not call `shouldRetry` and does not wait for a retry delay. The new `isAbortRejection(error, signal)` export identifies a cancel. To tell a cancel from a failure, call `isAbortRejection`, not `error instanceof PerpsError`. The Hyperliquid order reads use the same check: if the explorer read fails, the orders return without explorer links, also when the signal aborts later.
