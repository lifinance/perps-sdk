Lighter REST wire types now alias the generated models in `zklighter-perps` (ORD-1688). The `Lt` prefix stays on every export. The four order enums (`LtOrderStatusEnum`, `LtOrderTypeEnum`, `LtOrderTimeInForceEnum`, `LtOrderTriggerStatusEnum`) are now string literal unions, so an unknown Lighter literal fails to compile. The package imports the generated models with `import type` only, so the build output holds no reference to `zklighter-perps`.

The generated models declare members the hand-written types did not. `LtOrder` adds the required members `base_size`, `base_price`, `order_version`, `integrator_fee_collector_index`, `integrator_taker_fee` and `integrator_maker_fee`, and it changes `order_flags` from optional to required. `LtLiqTrade` adds the required members `ask_account_id` and `bid_account_id`. `LtPositionFunding` changes `discount` from optional to required. Every `Lt*` type is a read-only alias for a Lighter response body, and the SDK constructs none of them. A consumer that builds one of these types in a test fixture must add the new members.

The Lighter provider sets `noImplicitOverride: false` in its `tsconfig.json`. The generated `zklighter-perps/runtime.ts` omits the `override` keyword on the `name` member of `FetchError`. That omission raises TS4115, and `skipLibCheck` does not suppress it.
