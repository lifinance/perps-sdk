Safe venue-data converters. One bad venue row no longer fails a whole list.

`@lifi/perps-sdk`:

- Removed `parseDecimal`. There is no alias. Use `decimalStringToNumber` for a strict `DecimalString` read: it gives `undefined` for a missing or invalid value. Use `formattedStringToNumber` for the old behaviour, which reads a formatted display string.
- Added `asDecimalString`. It gives a `DecimalString` for a finite decimal string or number, and `undefined` for all other values. It never throws.
- Added `requireVenueDecimal(value, field, tool)`. It gives a `DecimalString` or throws a `PerpsError` (`SDKError`) that names the field and the provider. Account and balance math use it.
- Added `applySlippageToPrice`.
- Added `warnSkippedVenueRow`. The provider mappers use it to log each skipped row once.
- Added `asIsoTimestamp`. It gives an ISO 8601 string for a valid venue time, and `undefined` for all other values.
- Added `wsLog.skippedRow` and `wsLog.droppedRow`. The WebSocket handlers use them to log a skipped row once.
- `asDecimalString` gives `undefined` for a value whose exponent is above 1000 in magnitude.
- `formattedStringToNumber` now removes whitespace inside the string, for example `'- 5'` gives `-5`.

Provider packages:

- Removed the provider decimal helpers: Hyperliquid `toWireBig`, Lighter `toRequiredBig`, `toPositiveRequiredBig` and `toBigOrNull` (Lighter exported `toRequiredBig` and `toBigOrNull`), and Ondo `toWireBig`.
- `mapPosition`, `mapOrder` and `mapFill` in all three providers now return `Position | undefined`, `Order | undefined` and `Fill | undefined`. A row with an invalid required decimal gives `undefined` and one warning. An invalid optional decimal leaves the field out.
- The list methods and the WebSocket handlers skip a bad row and keep the other rows. `getOrder` throws `OrderNotFound` for a bad row.
- A row with an invalid date skips with one warning. An Ondo order with an invalid trigger price, or a limit order with an invalid price, skips with one warning.
- A portfolio-history point with an invalid time, account value or PnL skips with one warning. An invalid volume leaves the field out.
- The WebSocket order books skip a level with an invalid price or size. A Hyperliquid or Lighter book update with a valid price and an invalid size removes the old level at that price. No mapped output contains `NaN`.
- Hyperliquid `spotBalance` now takes `total` as a `DecimalString`.
- Lighter `getAccount` throws `SDKError` when an open position is not valid, because the account totals are then unknown.
- The account and balance decimal errors now start with the lowercase provider key, for example `ondo field ...` in place of `Ondo field ...`.
