Safe venue-data converters. One bad venue row no longer fails a whole list.

`@lifi/perps-sdk`:

- Removed `parseDecimal`. There is no alias. Use `decimalStringToNumber` for a strict `DecimalString` read: it gives `undefined` for a missing or invalid value. Use `formattedStringToNumber` for the old behaviour, which reads a formatted display string.
- Added `asDecimalString`. It gives a `DecimalString` for a finite decimal string or number, and `undefined` for all other values. It never throws.
- Added `requireVenueDecimal(value, field, tool)`. It gives a `DecimalString` or throws a `PerpsError` (`SDKError`) that names the field and the provider. Account and balance math use it.
- Added `applySlippageToPrice`.
- Added `warnSkippedVenueRow`. The provider mappers use it to log each skipped row once.

Provider packages:

- Removed the provider decimal helpers: Hyperliquid `toWireBig`, Lighter `toRequiredBig`, `toPositiveRequiredBig` and `toBigOrNull` (Lighter exported `toRequiredBig` and `toBigOrNull`), and Ondo `toWireBig`.
- `mapPosition` and `mapOrder` in all three providers now return `Position | undefined` and `Order | undefined`. A row with an invalid required decimal gives `undefined` and one warning. An invalid optional decimal leaves the field out.
- The list methods and the WebSocket handlers skip a bad row and keep the other rows. `getOrder` throws `OrderNotFound` for a bad row.
- The WebSocket order books skip a level with an invalid price or size. No mapped output contains `NaN`.
- The account and balance decimal errors now start with the lowercase provider key, for example `ondo field ...` in place of `Ondo field ...`.
